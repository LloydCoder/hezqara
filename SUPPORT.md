# Support

HEZQARA is proprietary software. Support channels depend on the type of request.

| Request | Channel |
|---|---|
| Confirmed security vulnerability | GitHub private vulnerability reporting from the repository **Security** tab; never use a public issue |
| Reproducible software defect | GitHub issue using the **Bug report** form |
| Feature/product proposal | GitHub issue using the **Feature request** form |
| Contribution/process question | Pull request or GitHub issue with the relevant context |
| Commercial/customer support | Contact the Tinlance/HEZQARA maintainers through the applicable private business channel |

## Before requesting help

Include the repository commit/version, environment, exact command or workflow, expected behavior, actual behavior, and a minimal reproduction using synthetic data.

Never include patient information, credentials, API keys, access tokens, private certificates, or other secrets.

For deployment failures, distinguish source-code failures from provider/platform failures such as Vercel quota or rate limiting. Include the provider error and deployment identifier when available.
